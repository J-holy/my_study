# 도메인 연결과 광고 붙이기

2026-10-31 기준 정리. 지금 사이트 주소는 `https://j-holy.github.io/my_study/` 입니다.

## 왜 도메인이 먼저인가
- **애드센스는 `github.io/my_study` 같은 하위 폴더 주소를 사이트로 등록할 수 없습니다.** 내가 소유한 도메인(최상위 주소)이어야 합니다.
- `ads.txt`, `robots.txt` 는 주소 맨 위(`도메인/ads.txt`)에 있어야 읽힙니다. 지금 주소에서는 `j-holy.github.io/ads.txt` 가 되어 이 저장소로는 둘 수 없습니다.
- 그래서 광고 신청은 도메인을 연결한 뒤에 합니다. 그 전에 할 수 있는 일(아래 1단계)은 끝내 두었습니다.

## 1단계: 지금 해 둔 것 (도메인 없이 가능)
- [x] 개인정보처리방침 `privacy/` (애드센스 필수, 광고 쿠키 안내 포함)
- [x] 소개와 문의 `about/` (문의는 GitHub 이슈. 이메일을 원하면 `about/index.html` 의 문의 부분에 추가)
- [x] 사용법과 자주 묻는 질문 `guide/` (도구 사이트는 글이 적어 "가치가 낮은 콘텐츠"로 거절되기 쉬워서, 검색엔진이 읽을 수 있는 글 페이지를 만듦)
- [x] 홈 아래에 사용법 · 소개 · 개인정보처리방침 · 문의 링크
- [x] 검색·공유용 정보: 페이지 제목, 설명, `og:` 태그, 파비콘(`favicon.svg`)

## 2단계: 도메인 산 날 할 일
1. **도메인 구입**: 가비아, 카페24 같은 국내 업체나 Cloudflare, Porkbun 같은 해외 업체 어디든 됩니다. `.com` 이나 `.kr` 추천.
2. **GitHub에 도메인 인증 (권장)**: GitHub 프로필 Settings → Pages → Add a domain. 안내대로 DNS에 TXT 레코드를 넣고 Verify. 다른 사람이 내 도메인을 가로채는 걸 막아 줍니다.
3. **DNS 설정** (도메인 업체 관리 화면):

   | 종류 | 이름(호스트) | 값 |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | AAAA (선택) | `@` | `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153` |
   | CNAME | `www` | `j-holy.github.io` |

   Cloudflare를 쓴다면 처음에는 주황 구름(프록시)을 꺼 두세요(DNS only). 그래야 GitHub가 HTTPS 인증서를 발급합니다.
4. **저장소에 도메인 등록**: `my_study` 저장소 Settings → Pages → Custom domain 에 `example.com` 입력 → Save. (저장소에 `CNAME` 파일이 생깁니다. Claude에게 맡겨도 됩니다.)
5. **HTTPS**: 인증서가 나오면(몇 분 ~ 하루) 같은 화면의 **Enforce HTTPS** 체크.
6. **Claude에게 도메인 알려 주기**: 아래를 한 번에 처리합니다.
   - `CNAME` 파일, `robots.txt`, `sitemap.xml`, 각 페이지의 대표 주소(`canonical`, `og:url`)
   - README 주소 갱신

이렇게 하면 `j-holy.github.io/my_study/` 로 들어와도 새 도메인으로 자동으로 넘어갑니다.

### 도메인을 바꿀 때 주의할 점
- **브라우저에 저장된 내용은 옮겨지지 않습니다.** 단어 목록, 오답노트 보관함, 서버 설정은 주소별로 따로 저장되기 때문에, 새 주소에서는 처음 쓰는 것처럼 비어 있습니다. 필요한 단어 목록은 미리 복사해 두세요. 서버 설정은 기본값(Pi 서버)으로 다시 잡힙니다.
- **라즈베리파이 서버의 허용 주소(CORS)**: 서버가 `https://j-holy.github.io` 에서 오는 요청만 받도록 되어 있다면 새 도메인도 추가해야 글자 읽기와 시험지 저장이 됩니다. 서버 코드는 `academy-voca` 의 `server/ocr_server.py` 에 있습니다. 도메인을 연결한 뒤 단어 시험지에서 **연결 확인**을 눌러 보면 바로 알 수 있습니다.

## 3단계: 광고 신청 (도메인 연결 후)
1. **Google Search Console**에 도메인 등록 → `sitemap.xml` 제출. 검색에 몇 페이지라도 잡힌 뒤 신청하는 편이 승인율이 높습니다.
2. **애드센스 가입** → 사이트에 도메인 추가 → 받은 확인 코드(`<script ... adsbygoogle.js?client=ca-pub-...>`)를 Claude에게 주면 모든 페이지 `<head>` 에 넣습니다.
3. **ads.txt**: 애드센스가 알려 주는 한 줄(`google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0`)을 `ads.txt` 로 저장소 맨 위에 둡니다.
4. **심사 대기**: 보통 며칠 ~ 몇 주. 거절되면 사유를 보고 글 페이지를 보강합니다.
5. **동의 메시지(쿠키 동의)**: 유럽·영국 방문자에게 광고를 보이려면 Google 인증 동의 관리 도구가 필요합니다. 애드센스의 **개인 정보 보호 및 메시지** 메뉴에서 켜면 되고, 코드 수정은 필요 없습니다. 한국 방문자만 대상이면 급하지 않습니다.
6. **광고 위치**: 도구 화면(시험지 만들기, 사진 편집) 안에는 넣지 않고 홈, 사용법, 소개 같은 글 페이지에만 둡니다. 도구 안 광고는 잘못 누르기 쉬워 정책 위반이 되기 쉽고, 쓰는 사람도 불편합니다.

## 승인에 도움이 되는 것
- 사용법 글을 도구별로 더 늘리기(예: "교재 사진으로 단어 시험지 만드는 법" 같은 따로 된 글). 글 페이지가 많을수록 유리합니다.
- 모든 페이지에서 메뉴로 개인정보처리방침과 문의를 찾을 수 있게 유지하기(지금 되어 있음).
- 공사 중인 페이지, 빈 페이지 두지 않기.
